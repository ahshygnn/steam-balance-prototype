# 换 Steam 余额 · 交互原型

团队评审用的静态 HTML 原型。当前版本：UI 修改 7。

## 在线预览

<https://ahshygnn.github.io/steam-balance-prototype/>

## 页面

| 页面 | 说明 |
| --- | --- |
| [主流程原型](./index.html) | 完整链路：设置目标余额 → 购买饰品 → 等待到货 / 补购 → 出售换余额 → 兑换记录 |
| [边界① 购买时账号库存余量不足](./edge-1-inventory-short.html) | 打开即边界态。库存余量 3 把，需购 43 把被拦下，弹窗引导「前往清理库存」或「返回修改目标 Steam 余额」 |
| [边界② 补购超系统在售库存](./edge-2-system-stock-short.html) | 打开即边界态。缺口 3 把、系统在售仅 2 把，弹窗给出最多可兑换余额与差额，建议自行充值 |
| [边界③ 补购超账号库存余量](./edge-3-quota-short.html) | 打开即边界态。缺口 5 把、库存余量仅 3 把，可「前往清理」（数量不变）或「取消」（数量收缩到余量并标红） |

边界页顶部有红框横幅标明场景，右上角「演示」菜单里可一键重演本页边界场景。

## 本版改动

- 首页加返回箭头；「兑换记录」筛选改为横向 tab（全部 / 已完成 / 等待到货 / 需补购），去掉下拉
- 目标余额输入栏改为空态 + 灰色占位提示「请输入金额，当前最多可输入2550元」
- 「● Steam交易正常」上移到购买模块顶部
- 状态合并：去掉「待出售」，全部到货即「已完成」
- 补购区加红色时限提示「补购需在24h内完成，否则视为放弃补购。」
- 购买模块加账号库存检测行，样式与「● Steam交易正常」一致
- 商品卡改三栏字段：在售最低 / 在售最高 / 预估花费；移除卡片内的购买数量调节
- 去掉已购态折叠区里的「查看订单明细」
- 新增上述三个边界兜底演示页

## 说明

所有订单、支付、补购和通知均为演示，不发生真实交易。演示状态保存在各自浏览器的 localStorage 中，换浏览器或清缓存即重置；想换情境（如账号容量不足、行情异常）用右上角「演示」按钮切换。

请勿在原型中存放真实账号凭证或用户数据。
